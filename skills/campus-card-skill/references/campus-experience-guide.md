# 跨卡实战经验

这是从本地作品归纳的设计方法，不代表卡已通过长聊测试。具体来源见 [来源表](experience-sources.md)；不要照抄原卡的人物、成人内容或绕过模型约束的指令。

| 参考 | 可复用方法 | 迁移时要补的条件 |
|------|------------|------------------|
| 校园卡 | 目标、资源、成绩/关系与事件互相影响；标签落为行为与例外 | 日常对话不必算精力；关系不能仅靠轮数升级 |
| 多人日常题材 | 多人作息、在场条件、信息传播与第三方后果 | 不在场 NPC 不自动知道密谈；私密事件不经全知面板泄露 |
| 阶段交易题材 | 提出需求、报价、接受/还价、履约、结算的交易链 | 接受前不扣代价；同一契约只结算一次；拒绝仍有内容 |
| 循环叙事题材 | 本轮与跨轮状态分离；线索集合与结局条件 | 列出每个字段是否重置；线索不能重复计数；结局明确判定 |
| 单人对话题材 | 表层行为、内在动机、分层线索与单人声音 | 秘密不必每轮提醒；不把所有角色都写成同一种反差 |
| 空山教程 | 规则、世界观、人设分工；把真相写给叙述引擎 | MMD 字数上限和触发规则不跨平台通用；真相不等于角色知情 |

## 选择真正联动的机制

先挑一条核心循环。例如经营卡“接单 → 花费备件/时间 → 交付 → 收款/声誉 → 新订单”；悬疑卡“发现 → 核实 → 推断 → 行动 → 新线索”。没有影响后续选择的字段删掉或留在普通叙述中。

事件由条件、角色目标或未完成事项引出。随机池用于增加变化，不能每几轮无视现场强塞事件。间隔和事件数量是可调节奏，允许安静、失败、放弃与分支汇合。

## 让人物生态独立运转

每位常驻人物有自己的目标和日程，不都围着玩家转。对话聚焦在场且有动机发言的人；共同经历对各人的影响可以不同。新 NPC 用最小档案登记，只留存会再次影响剧情的信息。

“不喜欢玩家”不等于持续羞辱玩家；“熟悉”不等于认同所有请求；“好感”不自动等于信任、承诺或同意。用事件与具体关系事实支撑变化。

## 把故障转成可执行修复

- 数值漂移：找更新规则和唯一状态源；可用明确计数或档位，不一律删数字。
- NPC 全知：记录“谁通过什么途径知道”，不只反复写“禁止全知”。
- 秘密拖到无穷：给线索机会、必要条件和替代发现路径。
- 规则太多：保留影响选择的部分，删除重复注入与机械频次。
- 引导入口失效：提供纯文本说明和默认开场，保证不依赖按钮或脚本也能开始。
- 记忆越写越长：固定档案、当前状态、关键事件分开；合并已完成的重复日常。

新增经验按“适用场景 → 观察到的问题 → 最小修复 → 如何复测”记录，不增加跨题材铁律。
