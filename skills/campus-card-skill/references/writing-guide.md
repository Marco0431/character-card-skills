# 从设定到可玩的卡

## 先确定体验

从用户描述提炼：玩家扮演谁、主要和谁互动、常做什么选择、这些选择会改变什么。记录平台和已有功能；缺少背景细节可以提出默认方案，不用先问完一整张问卷。

| 卡型 | 优先投入 | 有证据需要时再加 |
|------|----------|------------------|
| 单人对话 / 陪伴 | 行为逻辑、声音、共同处境 | 关系状态、日常事件 |
| 群像 / 社会模拟 | 在场名单、独立目标、信息传播 | 作息、资源、事件调度 |
| 悬疑 / 探索 | 真相、线索路径、知情边界 | 发现集合、失败后继续的路径 |
| 经营 / 系统 / 循环 | 成本、结算、存档与重置 | 可执行变量系统、可验证随机机制 |

不要规定每卡必须 3–5 套规则、若干十条世界书或某种文风。题材没有通用黑名单。

## 先做最小可玩片段

先写角色核心、必要世界规则、一段开场和一个完整的“行动 → 反应 → 后果 → 下一步”片段。用户没有确定设定时，可用它检验方向，再扩充背景。改现有卡从实际故障切入：谁 OOC、哪条状态漂移、哪次触发失败，不无差别扩写。

示例：夜班修理铺。店主想按时关门却不能放着故障设备不管；玩家可以急修、砍价或明天来取。急修消耗备件并产生欠款，拒绝交易也能推进对话。这个片段比三页履历更容易暴露玩法问题。

## 内容分工

- **人物核心**：身份、目标、行为倾向、关系底线。每轮需要的信息保持可见。
- **按需背景**：过去事件、场所、配角、物品。条目被单独召回时能读懂，正文写清主体，不依赖仅供作者看的标题。
- **状态协议**：唯一状态源、更新与重置规则。见 [状态与记忆](state-and-memory-guide.md)。
- **文风样例**：少量覆盖不同处境的正面例子，避免把冗长禁词清单发送给模型。
- **呈现层**：叙事、必要状态、引导页。先能读能玩，再做样式；界面字段对应真实状态。

ST description 可放核心人设，世界书承载可检索内容；延续已有“全部人设入世界书”结构也可以，但要保证关键设定确实注入。taberna description 在本地样例里承担简介/引导页，不能机械搬入 ST 字段含义。

## 声音与开场

按 [角色与开场](character-card-guide.md) 写情境样例：日常、被拒、压力、关系变化。样例展示不同判断，避免四句话都同一种“傲娇反应”。

开场包含可感知处境和一个可回应的问题/动作，不代替玩家决定。多个开场让冲突或相处方式不同，而不只是换地点。无配置也能默认开始；引导页只是入口之一。

## 预算与取舍

分开看固定内容、当轮召回、历史/记忆、输出空间。计入格式模板与重复注入；页面 CSS 是否进入提示词以平台实测为准。没有模型分词器时只报字符数，不把中文字数当 token，也不沿用其他平台的“15000 字”硬上限。

超出目标预算时先删重复规则与无决策作用的设定，再把低频内容转按需；最后才压缩核心人设。群像测试多角色同时到场的高负载场景。

## 验收与迭代

按 [验证方法](validation-guide.md) 检查成品。记录失败输入、前态、实际行为、期望行为和相关条目；改最直接的规则后复测。没有新失败，不再叠加一串“绝对禁止”。经验来源见 [来源表](experience-sources.md)。
