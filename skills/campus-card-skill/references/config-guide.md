# SillyTavern 世界书配置

用于 ST，不能直接套用 taberna 数字枚举。平台依据与版本核查入口见 [来源表](experience-sources.md)。

## 按运行语义配置

- 核心身份、每轮生效规则保持可用；低频背景按需加载。单角色不等于全部蓝灯，纯世界书也不等于全部常驻。
- `constant` 表示不依赖关键词的激活方式；仍要考虑启用状态、概率和预算等限制。
- `scanDepth` 表示扫描消息数，不是固定的用户/AI 轮数。未覆盖的值按平台全局配置继承，不能把 `null` 解释成必定扫描全部历史。2 可作为短场景的起点，离场、别称、长回复后需要实测。
- `preventRecursion=true` 阻止本条触发其他条目；`excludeRecursion=true` 阻止本条被递归激活。无依赖需求时可采用双 true 降低意外联动；有明确依赖链则按图配置，检查环路和预算。不要把“双 true”称为开启双递归。
- `sticky/cooldown/delay`、次级关键词和 inclusion group 仅在目标版本支持时使用，分别验证持续、冷却、延迟与互斥，不将它们当作任意剧情状态的等价物。
- 插入位置和顺序控制注入；D0 适合短的当轮约束，不是所有规则都应放的唯一位置。保留已有合理配置，不因模板重排整本世界书。

## 配置与命令参数是两层

独立 ST 世界书常见 `entries` 字典、`key`、`disable`、`uid`；嵌入角色卡的 Character Book 常见 `entries` 数组、`keys`、`enabled`、`id` 与 `extensions`。不要按同一 schema 写入；以当前导出和脚本转换逻辑为准。

JSON 关键词通常使用数组，具体以目标平台导出为准。使用支持的数组字段保留各关键词；正则中的逗号不能靠简单 split 自动迁移。

## 从检索用例设计条目

每条记录主体、何时需要、何时不需要、关键词/条件、位置、预算优先级。只配置确有用处的字段。内容能单独读懂，不能只在条目标题写主语。

至少检查：全名、昵称、代词续聊、同名误触、离场、多角色同场、预算竞争。代词续聊容易丢失核心信息，可保留精简角色核心、使用已验证的持续激活机制或在场摘要，避免每轮复述全部人名造成全员触发。

## 工程操作

1. 用 `query.py <worldbook.json> --brief` 获取 ID 与结构。
2. 核对原文件结构与查询工具的 `--help`。
3. 更新权威源，在副本/输出路径构建，核对条目增删、未知字段和配置差异。
4. 用 [审计与试跑](validation-guide.md) 检查结构及实际激活。命令退出成功不是语义正确的证明。
